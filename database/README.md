# DecryptMe database

MySQL 8.0 schema for the DecryptMe user and point system.

## Run in MySQL Workbench

1. Open MySQL Workbench and connect to your MySQL server.
2. Open `database/schema.sql`.
3. Click **Execute** (the lightning bolt) or run the whole script.
4. Refresh the **SCHEMAS** panel. The `decryptme` database should appear.

Or run it from a terminal:

```powershell
mysql -u root -p < database/schema.sql
```

## What the schema contains

| Table | Purpose |
| --- | --- |
| `users` | Accounts and cached leaderboard totals |
| `categories` | Challenge categories such as Forensics and Cryptography |
| `challenges` | Challenge metadata, points, and hashed flags |
| `challenge_steps` | Ordered steps shown in the challenge modal |
| `solves` | One row per user/challenge solve |
| `flag_attempts` | Audit log of hashed flag submissions |
| `point_transactions` | Append-only ledger of all point changes |
| `achievements` | Achievement definitions |
| `user_achievements` | Achievements unlocked by users |

Views:

- `v_leaderboard`
- `v_user_profile_stats`
- `v_recent_activity`

## Award points for a solve

```sql
CALL award_challenge_points(1, 1);
```

This inserts the solve, adds a ledger entry, updates the user's total points,
and increments their solved count in one transaction. Calling it twice for the
same user and challenge raises an error and changes nothing.

## Check the leaderboard

```sql
SELECT *
FROM v_leaderboard
ORDER BY rank_position
LIMIT 10;

SELECT *
FROM v_user_profile_stats
WHERE user_id = 1;
```

## Important security notes

- `users.password_hash` must be generated by the backend with Argon2, bcrypt,
  or another password hashing algorithm. Never store plain-text passwords.
- `challenges.flag_hash` must contain a SHA-256/HMAC hex hash generated by the
  backend. Never store or return the actual flag.
- The frontend must never send point values to the database. Points come from
  the challenge row and are applied by `award_challenge_points`.

## Time zone

Timestamps are stored as `DATETIME(6)` and should be treated as UTC. Set the
connection time zone in the backend:

```sql
SET time_zone = '+00:00';
```

Alternatively, configure MySQL with `default-time-zone='+00:00'` in `my.ini`.

## Reset the database

```sql
DROP DATABASE decryptme;
```

Then run `schema.sql` again.
